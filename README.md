# Phase Balance Analysis Toolkit

This repository contains the code, notes, and experiments that support my master's thesis on
phase imbalance across Veitur's low-voltage distribution network. It bundles together the data
collectors for Janitza GridVis meters, reusable power-quality metric calculators, exploratory
notebooks, and supporting documentation used to quantify thermal and voltage imbalance risks in
substations and feeders.

## Key capabilities

- **GridVis data access** – `src/phasebalance/janitza_fetch.py` constructs authenticated REST
  requests against the on-premise GridVis API and handles time-base fallbacks, timezone-aware
  windows, and retry logic.
- **Bulk metric extraction** – `src/phasebalance/janitza_scrapper.py` orchestrates device/channel
  resolution, downloads Janitza series, averages the readings over a study window, and derives a
  consistent metric table (Current Unbalance Ratio, Voltage Unbalance Factor, neutral current
  estimates, etc.). Results are written to timestamped CSV files inside `results/`.
- **Reusable imbalance formulas** – `src/phasebalance/phase_unbalance_utils.py` implements the
  distribution imbalance index (DIB), multiple flavours of CUR, voltage unbalance factors, sequence
  component ratios, and helper routines for safely aggregating partially available measurements.
- **Exploratory analysis** – interactive notebooks under `notebooks/` provide ad‑hoc visualisation
  and validation workflows for substations, complementing quick-look charts in `docs/`.
- **Metadata scaffolding** – `metadata/` stores exported device inventories (and, locally,
  capabilities tables) that allow the scripts to map logical measurements (e.g. IN01, L1) to their
  physical Janitza channels.

## Getting started

1. **Prerequisites**
   - Python 3.11+ is recommended (the dependency set has been validated there).
   - Access to the Or.is VPN or an on-site network is required for GridVis API calls.
   - Credentials or an API token with permission to query the relevant Janitza devices.

2. **Clone and create an environment**

   ```bash
   git clone git@github.com:your-user/Jasonaq_thesis.git
   cd Jasonaq_thesis
   python -m venv .venv
   source .venv/bin/activate  # On Windows use: .venv\Scripts\activate
   pip install --upgrade pip
   pip install -r req.txt
   ```

3. **Configure environment variables**

   The fetch utilities use the `requests` session directly; if GridVis requires authentication,
   export the expected headers/tokens (e.g. `GRIDVIS_AUTH_TOKEN`) before running the scrapers or
   extend `janitza_fetch.py` to inject them.

## Usage

### 1. Export device metadata

Populate `metadata/devices.csv` (already included) and `metadata/capabilities.csv` (exported from
GridVis' capability reports). The latter is required for resolving which backend channels to fetch
for each logical measurement.

### 2. Run the Janitza scraper

Edit the configuration block at the bottom of `src/phasebalance/janitza_scrapper.py` to match your
study period and time base, then execute:

```bash
python -m src.phasebalance.janitza_scrapper
```

The script will:

1. Load device and capability metadata.
2. Resolve which measurement channels (e.g. `IN01`, `L1`) to request for each device.
3. Fetch current, voltage, and sequence magnitudes for the configured window (with automatic
   fallback timebases when data is missing).
4. Compute imbalance metrics using `compute_meter_metrics`.
5. Write a CSV file to `results/metrics_results_<timestamp>.csv` for downstream analysis.

### 3. Work with the metrics interactively

Open the notebooks under `notebooks/` to visualise phase loading, estimate thermal losses, or cross
reference Janitza readings with smart-meter aggregates. The notebooks assume the CSVs generated by
the scraper live in `results/` and that the `phasebalance` package is importable (use
`pip install -e .` if you prefer editable installs).
